# Tofu gallery copy

This repository is Tofu's copy of **usememos/memos** (licence: MIT), listed in Tofu's app gallery as **Memos**: a personal note timeline. You write short notes in Markdown, with tags, attachments, comments and a calendar, and keep them on your own server.

- `main` mirrors the upstream repository and is never committed to by Tofu.
- `tofu` carries Tofu's own changes; tags named `pin/<date>` mark the versions the gallery points to. The current pin is `pin/2026-10-25`.
- A visitor who chooses this app gets a private snapshot of the pinned version in their own Tofu account. Their copy does not follow upstream updates.
- Upstream: https://github.com/usememos/memos at `2b2192d4e153bd04f1d325b60fd880cf00d68b01`, the v0.31.0 release (2026-09-19). `tofu` starts at that release, not at the newest commit on `main`: upstream commits daily and is between release candidates of its next version (26.10-rc.1), and a release is the state upstream tested as a whole.

## How Tofu runs it

- Framework preset `container`, root folder: the repository root. Tofu builds the root `Dockerfile` and runs the image as a service, so there is no separate install command, build command or output directory.
- The `Dockerfile` has three stages:
  - The web app, on `node:24-alpine`: `npm install -g pnpm@11.0.1` (the version `web/package.json` names), `pnpm install --frozen-lockfile`, then `pnpm release`, which runs `vite build --mode release` into `server/frontend/dist`.
  - The server, on `golang:1.27.3-alpine` (`go.mod` asks for Go 1.27.0): `go build ./cmd/memos` with the web app embedded, as upstream's `scripts/Dockerfile` does, with BuildKit cache mounts (`RUN --mount=type=cache`).
  - The image, on `alpine:3.21` as upstream's: the binary, upstream's `scripts/entrypoint.sh`, and `tofu-entrypoint.sh`, which the image starts through.
- Database: PostgreSQL, the copy's Tofu database, read from `DATABASE_URL`. Memos makes its own tables when it starts: on an empty database it runs its full schema (`store/migration/postgres/LATEST.sql`), and after an upgrade its own numbered migrations. There is no `supabase/migrations` folder, so Tofu applies nothing before the build. Without `DATABASE_URL`, Memos falls back to SQLite under `/var/opt/memos`, which is lost on every restart.
- Settings: Tofu sets `PORT` and `DATABASE_URL`, and the gallery saves `MEMOS_INSTANCE_URL`, the copy's own address, before its first deploy. Nothing has to be set by hand. An owner may add `MEMOS_DISALLOW_USER_REGISTRATION=true` (see "Signing up") and any of Memos' own options: each flag in `cmd/memos/main.go` is read from `MEMOS_` plus its name in capitals, with `_` for `-`.
- Secrets: Memos makes its own key for signing sign-in tokens at its first start and keeps it in the database. A copy needs no secret setting, and restarts, redeploys and a changed `DATABASE_URL` leave sign-ins alone.

## What Tofu changes

Every commit on `tofu` starts with `Tofu:` and says why. Every changed file carries a `Tofu (2026-10-25)` note at the change.

- `Dockerfile` (new) and `.dockerignore`. Upstream's `scripts/Dockerfile` needs the web app built outside Docker first (its CI runs `pnpm release` before `docker build`), so Tofu could not build it from the repository alone. The root `Dockerfile` builds `web/` in its first stage and then follows `scripts/Dockerfile`, without its cross-compiling arguments. `VERSION` defaults to `0.31.0` and `COMMIT` to `unknown`. `.dockerignore` no longer leaves `web/` out of the build context, only `web/node_modules/` and `web/dist/`. `scripts/Dockerfile` is unchanged.
- `tofu-entrypoint.sh` (new). The image starts through it, and it ends by running upstream's `scripts/entrypoint.sh`, which runs the server:
  - `PORT` becomes `MEMOS_PORT`. Without `PORT`, the image's 5230 stays.
  - `DATABASE_URL` becomes `MEMOS_DRIVER=postgres` and `MEMOS_DSN`, with `binary_parameters=yes` added to the URL. Memos talks to PostgreSQL through lib/pq, which otherwise sends every query that has parameters in two round trips, a prepare and then an execute. Tofu's `DATABASE_URL` goes through a transaction pooler, which may hand the second round trip to another server connection. The query then fails with `pq: unnamed prepared statement does not exist (26000)`, and Memos does not start. With `binary_parameters=yes`, lib/pq sends each query in one round trip. A `MEMOS_DSN`, a `MEMOS_DRIVER` or a `binary_parameters` the owner sets is kept as it is.
  - Upstream's entrypoint switches from root to user 10001 with `su-exec`. Only root may listen on a port below 1024, and Tofu's `PORT` is 80 unless the app sets another. So the server stays root when its port is below 1024, and also when `su-exec` cannot switch users on the host.
  - When the server does not run as root and cannot write `/var/opt/memos`, it keeps its scratch files in `/tmp/memos` instead.
- `store/instance_setting.go`, attachments. On PostgreSQL, while no storage setting has been saved, new attachments go into the database instead of onto the local disk, which does not survive a restart on Tofu. A storage the admin saves in Settings, local or S3, always wins. Attachments keep the storage they were saved to. SQLite and MySQL keep upstream's default, the local disk.
- `cmd/memos/main.go`, `internal/profile/profile.go` and `store/instance_setting.go`, sign-up. A new flag, `--disallow-user-registration`, read from `MEMOS_DISALLOW_USER_REGISTRATION`, keeps self-service sign-up closed whatever the admin's stored setting says (see "Signing up"). Memos keeps its own switch in the database, where only the admin can change it.
- `store/tofu_data_api.go` (new) and `store/migrator.go`. After its migrations, on a database that has Supabase's Data API roles (`anon` and `authenticated`), Memos turns on row-level security on its own tables in `public`: the 13 tables `LATEST.sql` makes, where its role owns them and they do not have it yet. Tofu's databases are Supabase PostgreSQL, and a database whose default privileges still give every new table in `public` to those roles would otherwise let anyone with the project's public key read and change Memos' tables through the Data API, including `user` with its password hashes. With row-level security on and no policy, those roles see no row. Memos' own connection owns the tables, so row-level security does not limit it. The step never turns row-level security off, touches no other table, and does nothing on a PostgreSQL without those roles. If it fails, Memos logs a warning and starts anyway.
- `web/src/components/MemoEditor/services/uploadService.ts`. A file of 2 MB or less is now uploaded in one call that carries its details, its bytes and the instruction to finish, which the server already accepts. Upstream's editor opens every upload with a call that carries no data and sends the bytes in later calls, while the server holds the upload in its own memory and a temporary file between calls. That breaks when the calls reach different instances or the server restarts between them. The single call is not retried, so a lost answer cannot store a file twice: the person adds the file again. Larger files still use upstream's chunked upload.

## Signing up

- Memos has its own accounts, not Tofu's sign-in. **The first account created on a new copy becomes its admin.** Until then, anyone who opens the address sees the page to create the admin account, so the owner should create their account first, or keep the copy private on Tofu until they have.
- After that, anyone who can open the address can sign up as a regular user until sign-up is closed. To close it, save `MEMOS_DISALLOW_USER_REGISTRATION` as `true` on the app's Keys & settings page and deploy again. New sign-ups are then refused (`user registration is not allowed`), the sign-in page hides its sign-up link, and existing accounts keep signing in. The first account can still be created while it is `true`.
- `false` (or no value) gives the decision back to the admin's own switch, Settings → System → "Disallow user registration". While the setting is `true`, that switch shows sign-up as closed, and if the admin saves the instance settings then, the stored switch is closed too: sign-up stays closed after the setting goes back to `false`, until the admin opens it in Settings.

## What works differently on Tofu

- **A public instance.** Because `MEMOS_INSTANCE_URL` is set at the first start, Memos makes the copy a public instance: signed-out visitors can open its Explore page, read memos marked Public, and reach its sign-in and sign-up pages. New memos are Private by default. The admin can turn off "Allow public access" in Settings → System; signed-out visitors then only reach shared memo links and the sign-in page.
- `MEMOS_INSTANCE_URL` also gives the address to email notification links, `robots.txt` and `sitemap.xml` (public instances only), and the origins Memos accepts. Email notifications need SMTP settings, which the admin enters in Settings; without `MEMOS_INSTANCE_URL`, Memos sends none.
- **Attachments are kept in the database** and count toward its size. The upload limit is upstream's 30 MB per file, which the admin can change in Settings. An admin who wants attachments elsewhere can add S3-compatible storage in Settings. Image thumbnails are cached in the server's scratch folder and made again after a restart.
- **Uploads over 2 MB, and importing memos,** still send their data in several calls that one server process holds in memory, and in a temporary file, for up to 30 minutes. If more than one instance of the copy runs and the calls reach different ones, or the server restarts in between, the upload fails ("upload not found") and has to be tried again.
- **Live refresh** sends changes to open pages over a stream held by one server process. If more than one instance runs, a change made through another instance shows when the page reconnects, which it does by itself, or is reloaded.
- **Rate limiting** counts sign-ups and failed sign-ins per visitor address. Memos trusts forwarding headers only from proxies in private address ranges (`MEMOS_TRUSTED_PROXIES`, default `private`). If Tofu's proxy reaches the container from a public address, every visitor appears as that one address, and the limits apply to everyone together.
- The server may run as root (see `tofu-entrypoint.sh` above).
